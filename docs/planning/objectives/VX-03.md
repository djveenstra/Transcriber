## Mission

Define stable, versioned contracts and a reversible storage/migration strategy for future processing engines without changing production code, data, schema, dependencies, models, or behavior.

## Why now

- Prerequisite objectives: VX-01 `PROCEED`; VX-02 inventory completed at `ASK USER`, with no dependency on VX-03 design.
- Risks and gaps addressed: R-01, R-02, R-04, R-05, R-08, R-14, R-19, R-28; missing normalized results, provenance, artifact placement, compatibility, and transcript-version semantics.
- Current evidence: `Recording` safely stores current JSON blobs and audio linkage, while future multi-engine/raw/versioned evidence would make that model fragile if appended without an artifact boundary.

## Technical approach

Design immutable envelope-and-payload artifacts with stable IDs, explicit schema/producer versions, monotonic attempt ownership, normalized time units, typed references, and provenance. Keep `Recording` as the Library index and compatibility projection while moving future raw/large/versioned evidence to an application-owned artifact directory. Require write-temp → sync/close → atomic rename → manifest compare-and-publish. Make migration additive, lazy, idempotent, and rollback-compatible.

## Data and migration

- Existing data read path: current `Recording` and audio path remain authoritative until a validated projection exists.
- New data/write path: design only; future artifact root scoped by recording ID with immutable artifacts and atomic manifests.
- Versioning: independent envelope, payload schema, producer, preprocessing, pipeline, calibration, and correction versions.
- Corruption behavior: isolate the bad artifact, fall back only through the authoritative `current.previous` pointer or legacy projection, preserve original audio/current blobs, and surface repair/reprocess.
- Rollback compatibility: old app continues reading legacy `Recording` fields; future code dual-writes compatibility projections until a separately approved retirement objective.
- User-data deletion: none in VX-03; future cleanup never treats original audio, verified transcripts, corrections, profiles, or enrollment data as cache.

After corrections, a one-line legacy compatibility label remained inconsistent and was fixed.

Final result: **`ALIGNED`**.

The Auditor confirmed consistent durable IDs, pointer-authoritative publication/fallback, legacy-preserved Human work, atomicity, corruption, rollback, cleanup, privacy, uncertainty, dependency, concurrency, and path safeguards.

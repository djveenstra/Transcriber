## Mission

Create reproducible mono 16 kHz working derivatives and conservative quality measurements while preserving every source audio byte and current processing behavior.

## Why now

- Prerequisites: VX-05 and VX-06 `PROCEED`.
- Primary risks: R-02 and future model-comparison inconsistency.
- Approved contract: `PreparedAudioV1` semantics from VX-03.

## Scope

### Allowed paths

- New audio-preparation/quality source files under `src/native/Transcriber2/Transcriber/`
- New focused tests and tiny programmatically generated fixtures under `TranscriberTests/`
- Planning/evidence files for VX-07

### Forbidden changes

- No replacement, rename, normalization, metadata edit, or deletion of original audio.
- No current recording/import/transcription/diarization pipeline switch to the derivative.
- No denoising, source separation, model/dependency/package/project/entitlement/schema/UI change.
- No private/repository audio, iOS/Python/legacy/asset/model-cache/research changes.

### Private-data permission

None. Tests generate PCM audio programmatically in temporary directories.

## Required implementation

- Versioned preparation recipe and result contract with source ID, source metadata, output metadata, time mapping, digest, byte count, algorithm versions, and regeneration key.
- Deterministic derivative naming and sidecar metadata.
- Conversion to mono 16 kHz PCM using system AVFoundation only.
- Preserve original sample rate, channel count/layout, duration, and format metadata.
- Reproducible measured duration, peak/RMS level, clipping count/ratio, silence ratio/regions, and conservative speech-activity regions with explicit thresholds/units/versions.
- Atomic derivative/sidecar publication, reuse only when source digest + recipe/version match, and interruption-safe invalidation.
- Cleanup/invalidation limited to the generated derivative/sidecar; never the source.

## Required tests

- Mono/stereo and non-16 kHz conversion; output format/frame count/time mapping.
- Original bytes/digest unchanged on success, failure, reuse, invalidation, and cleanup.
- Deterministic naming/reuse and recipe/source-change invalidation.
- Clipping, silence, level, speech regions, short/empty/invalid inputs, channel metadata.
- Atomic interruption leaves no authoritative partial result.
- Cleanup removes only generated derivative/sidecar.
- Reproducibility across repeated preparation.

## Data and migration

No `Recording` schema or existing app flow changes. The service writes only to an explicitly supplied derivative root and is not called by current production orchestration in VX-07.

## Validation

Run Mac build, full `TranscriberTests`, focused audio-preparation tests, diff scope, strict concurrency, pins, source-byte preservation, and rollback.

## Rollback

Remove the dormant service/tests and delete only test-generated temporary derivatives. Existing original audio, recordings, transcripts, and job/artifact infrastructure remain unchanged.
